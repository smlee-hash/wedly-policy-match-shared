# Collection count baseline after historical recovery

Goal: A normal bounded board collection must compare with the prior successful equivalent collection, never the whole open archive recently touched by backfill. Production GBIA restored via Mac returned75 valid rows at05:11UTC but was rejected against231 database open rows after archive recovery. Other sources can encounter the same mismatch as historical backfill advances.

Keep real sudden-drop and structural validation. Add a source-specific versioned JSON cache baseline written only after successful complete fetchBoardAll resolution, storing the fetched announcement count and observation time plus a stable signature of relevant collection configuration. Baseline validity: exact source/config, finite nonnegative safe integer count, valid recent timestamp within existing26-hour horizon, no future timestamps. Missing/stale/malformed/mismatched/read-failed baseline means first comparable collection (0), never fallback to aggregate archive counts. Preserve source failure reporting and pagination caps; do not reset failure counters manually or mark failed collection successful. If baseline persistence fails, retain valid fetched results and warn without secrets; do not overwrite an existing baseline on fetch failure.

Signature must remain stable between Next bundled runtime and tsx manual runtime: use relevant plain config fields and sample list URLs, not function.toString or build commit. Existing consumers' dependency interfaces remain compatible. No schema, UI, hosts, proxy, guard threshold, date inference, or page-limit changes.
